# plan/02 架构与技术选型

> 本文件回答三件事：**为什么这么分层**、**边界画在哪**、**构建与运行怎么保证确定性**。
> 数值口径不在本文件定义（唯一出处是 `mailvault/constants.py`，见 `plan/04` §3）。

---

## 1 约束（来自题面，不可协商）

| 约束 | 来源 | 对架构的后果 |
|---|---|---|
| 审计阶段零网络 | 题面 §1 / §7 隐私红线 | 所有求值器只吃 `snap.json`；`socket` 只能在 `mailvault/net.py` 出现，且只被 `snapshot fetch` 导入 |
| 不读系统时钟做判定 | 题面 §3 确定性纪律 | 时间只从快照元数据取；代码里禁止 `datetime.now()` / `time.time()` |
| 两次运行字节级一致 | 题面 §3 / 评分栏 2 | 单一序列化入口（`canonical.py`）+ 字典键序固定 + 浮点定点化 |
| 退出码一处定义 | 题面 §3 | 只在 `exits.py` 定义映射，CLI 层只做「异常 → 退出码」转换 |
| 判定必须挂 `evidence_ref` | 题面 §3 / §5 栏 3 | 账本装配器在构造期校验，缺条款的判定降级为 `undecidable` |
| 不允许"进箱概率" | 题面 §7 红线 | 词汇表门禁（`tools/check_forbidden_terms.py`，M6 落地） |
| Python 3.11+ | 题面 §1 | `requires-python = ">=3.11"`；可用 `tomllib`、`match`、`X | Y` |

## 2 分层

```
┌──────────────────────────────────────────────────────────────┐
│ L5  CLI 层            mailvault/cli.py  __main__.py          │
│     子命令冻结：snapshot fetch / audit / whatif / diff        │
│     职责：参数解析、异常→退出码、输出落盘；不含任何判定逻辑    │
├──────────────────────────────────────────────────────────────┤
│ L4  编排/账本层       mailvault/ledger.py  render.py         │
│     职责：把各模块结论装配成 checks[]、算 summary、渲染两轨    │
│     不变量：无 evidence_ref → 不进账本；渲染零外链、零判定    │
├──────────────────────────────────────────────────────────────┤
│ L3  判定层            mailvault/modules/{spf,dkim,dmarc,      │
│                              reconcile,whatif}.py            │
│     职责：纯函数式求值，输入 (Snapshot, Query, Eml) → 结果    │
│     约束：不得 import net / 不得读时钟 / 不得读环境变量        │
├──────────────────────────────────────────────────────────────┤
│ L2  输入层            snapshot.py  query.py  eml.py  psl.py  │
│     职责：解析 + 校验 + 结构化；坏输入 → InputError(exit 3)   │
│     约束：schema_version 单点比对，未知版本显式拒绝            │
├──────────────────────────────────────────────────────────────┤
│ L1  基础层            constants.py  exits.py  canonical.py   │
│     crypto/{der,rsa}.py                                      │
│     职责：口径常量、退出码、确定性序列化、密码学原语           │
│     约束：零依赖、无业务语义、可被全层引用                    │
├──────────────────────────────────────────────────────────────┤
│ L0  网络层（孤立）    net.py                                 │
│     全仓唯一的 socket 出口；只被 cli 的 snapshot fetch 分支用  │
└──────────────────────────────────────────────────────────────┘
```

**依赖方向单向向下**，L1/L2 不得 import L3/L4/L5。`tools/check_no_network.py` 用 AST 守门，
断言 L0 之外的任何模块都不出现 `import socket` / `import ssl` / `import http.*` / `import urllib.*`。

### 2.1 为什么判定层是"纯函数 + 显式输入"

判定的三个输入全部是磁盘上的文件（`snap.json` / `message.eml` / `query.json`），
没有隐式环境。这样才可能做到：

- **可复算**：同一份三件套 → 同一份 `verdict.json`（逐字节）；
- **可注入**：测试与 what-if 用同一入口，只是换一份快照/查询，不重写求值器；
- **可审计**：每个判定节点的输入输出都能落进 `trace[]`。

### 2.2 为什么 `snapshot fetch` 单独成层并用 AST 隔离

题面的隐私红线是"审计阶段零网络"。光靠"我记得不要联网"不算保证——必须有一条**能红的门**。
隔离方式：把 socket 相关 import 全部收进 `net.py`，再用 AST 守门扫描其余全部模块。
守门本身要能被变异验证（在 `spf.py` 里加一行 `import socket` → 门必须红）。

### 2.3 为什么不用 `src/` 布局

题面 §8 的目录约定明确写 `mailvault/ # 包源码`。题面是规格，**组件不另行发明目录形状**。
平铺布局在 `pyproject.toml` 里用 `[tool.setuptools.packages.find] include = ["mailvault*"]` 收敛，
避免把 `tests/`、`tools/` 误打进包。

## 3 确定性设计

| 风险 | 处置 | 守门 |
|---|---|---|
| 字典键序 | `canonical.dumps()` 递归排序键；全仓唯一 `json.dumps` 调用点 | AST 门：`json.dumps` 只允许出现在 `canonical.py` |
| 浮点表示 | 账本内不出现裸浮点：比率一律 6 位定点字符串（`"0.500000"`），计数用 `int` | `canonical.fixed6()` 唯一定点入口；测试断言类型 |
| 时间 | 只接受快照里的 ISO-8601 字符串；输出原样回显，不做时区换算 | 测试：源码中 `datetime.now` / `time.time` 零命中 |
| 集合/字典遍历 | 输出前一律显式 `sorted(...)`；不依赖插入顺序 | 双跑 diff 测试 |
| 文件路径 | 账本内**不写绝对路径**（脱敏 + 跨机可比）；需要指认时写相对仓库根或逻辑名 | 渲染测试断言无盘符 |
| 版本指纹 | `tool_version` 从 `mailvault.__version__` 取；参与 `ledger_id` | 定版时样例同轮重生成（`plan/05` §4） |
| 换行 | 所有落盘文本 `\n`；`.gitattributes` 全量 `eol=lf` | 渲染测试断言无 `\r` |

`ledger_id` 的定义：对"规范化输入 + 判定结果 + tool_version"的规范化 JSON 取 sha256。
**它必须是确定的**——同一输入两次运行相等；不同输入不相等（测试各一条）。

## 4 构建与发布形态

| 项 | 决定 | 理由 |
|---|---|---|
| 构建后端 | `setuptools>=68` + `pyproject.toml` | 标准库够用，无额外工具链 |
| 运行时依赖 | **零**（`dependencies = []`） | 零依赖 → CI 四矩阵不缺包、发布件自足、离线装包不受代理影响 |
| 测试依赖 | `pytest>=8`（`dev` extra） | 仅测试期 |
| 版本单一真源 | `mailvault/__init__.py` 的 `__version__` | `pyproject` 用 `dynamic = ["version"]` 引用；README 状态行引用 `v` 前缀 |
| 打包形态 | sdist（手写源码包口径，见 `plan/05` §4） | 无编译产物；发布附件与 tag 树逐字节同源 |
| CLI 入口 | `mailvault = "mailvault.cli:main"` | 同时支持 `python -m mailvault` |
| 最低版本 | 3.11 | 题面 §1 |

**加密原语选型**：DKIM 需要的 RSA 验签（PKCS#1 v1.5 / SHA-256）用标准库实现——
`hashlib` 出摘要，`crypto/der.py` 解 SubjectPublicKeyInfo，`crypto/rsa.py` 做 big-int `pow(m, e, n)`
并校验填充字节。约 150 行，收益是"零依赖"这条在 CI/离线/发布三处同时成立。
Ed25519 不在标准库内 → `ed25519-sha256` 签名一律判 `undecidable` 并写明"本工具不支持该算法，未做判定"，
**不判 fail**（题面 M2 验收 2 的同一条纪律）。
