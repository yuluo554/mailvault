## 2 CLI 契约（M0 冻结）

冻结子命令（题面 §8）：`snapshot fetch` / `audit` / `whatif` / `diff`。
新增子命令必须先写 `docs/backlog.md`。

```
mailvault [--version] <command> ...

mailvault snapshot fetch --eml <path> --query <path> -o <snap.json>
                          [--resolver <name>] [--psl <path>]

mailvault audit  --snapshot <snap.json> --eml <message.eml> --query <query.json>
                 [--json <out.json>] [--md <out.md>] [--strict-evidence] [--out-dir <dir>]

mailvault whatif --snapshot <snap.json> --eml <message.eml> --query <query.json>
                 --change <key=value> [--change ...] [--json ...] [--md ...]

mailvault diff   --baseline <verdict.json> --candidate <verdict.json> [--json ...] [--md ...]
```

**参数语义三条（M0 起就锁死）**：

1. `--change` 是**可重复**参数，不是逗号分隔（`--change p=reject --change t=y`）。
   文档与 parser 必须一致——`add_argument(action="append")`，**不加** `choices=`。
   若某天要支持逗号，必须同时改 README 与解析器，并加一条"文档 → parser 反射对账"测试。
2. 输出位置：`--json` / `--md` 是**文件路径**；`--out-dir` 是目录，给未指定路径的产物兜底。
   两者同时给时 `--json`/`--md` 优先，`--out-dir` 只影响默认文件名。
3. 未知 `--change` 键或不可解析的值 → `InputError`（exit 3），**不做静默忽略**。

**默认行为**：`audit` 不给输出参数时，把 `verdict.json` + `verdict.md` 写到 `--out-dir`（默认当前目录）。
`--json -` 表示写 stdout（仅 JSON 轨道，便于管道）。

## 3 各模块详设

### 3.1 `snapshot.py`（M1）

`snap.json` 结构（与 `plan/01` §4 一致）：

```json
{
  "schema_version": 1,
  "fetched_at": "2026-10-19T18:35:00Z",
  "resolver": "synthetic",
  "psl_version": "2026-10-01",
  "psl_date": "2026-10-01",
  "queries": [
    {"qname": "_dmarc.example.invalid", "qtype": "TXT", "rcode": "NOERROR",
     "answer": ["v=DMARC1; p=none; rua=mailto:dmarc@example.invalid"], "ttl": 300}
  ]
}
```

**关键语义**（题面要求"逐查询 qname/qtype/rcode/answer/ttl"）：

- `queries` 是**有序列表**，不是字典——同一 `(qname,qtype)` 可有多次查询（CNAME 链、重试）。
- 查询接口 `Snapshot.resolve(qname, qtype) -> Resolved` 返回**第一次命中的那一条**（按列表顺序），
  并把命中下标写进 `trace`。这样"快照里查了两次结果不同"这种真实情况不会被静默掩盖。
- `rcode` 非 `NOERROR`（如 `NXDOMAIN`）时 `answer` 必须为空列表；不满足 → `InputError`。
- 缺 `psl_version` / `psl_date` → `InputError`（题面 §2.5 灰区 3 要求输出必须带）。
- 未知 `schema_version` → `InputError`，错误信息列出支持版本。

### 3.2 `modules/spf.py`（M2）

**核心接口**：

```python
def check_host(snap: Snapshot, ip: str, domain: str, helo: str, *,
               budget: Budget, trace: Trace) -> SpfResult
```

**预算账本**：`Budget` 是可变对象，每消费一格 `consume(kind)` 记录 `(kind, node_id, ref)`；
超限时**不抛异常**，而是在结果上标 `limit_hit`，由调用方决定 `permerror`（term/MX/PTR，MUST）
还是 `undecidable` + 告警（void，SHOULD）。

**include 树**：完整展开，不因第 10 个 term 截断；每个节点带
`consumes_term` / `receiver_would_stop_here`（第 11 个起为 true）。
节点 id 规则：根 `n0`，第 i 个 include 子节点 `n<i>`，嵌套 `n<i>.<j>`（K12）。

**RFC 7208 测试集接入**：`fixtures/spf/rfc7208-tests.yml`（pyspf 原始文件，保留 LICENSE）。
runner 把 yml 里的 `dns` 桩转成合成 `Snapshot`，逐条跑 `check_host()`。
203 用例通过率 ≥ 95%；失败逐条登记 `data/rfc7208-failures.md`。

### 3.3 `modules/dkim.py`（M3）

**多签名**：遍历 `DKIM-Signature` 头**全部**条目（同名头可重复），逐条独立求值，不短路。
每条输出 `selector` / `d` / `i` / `a` / `c` / `bh_matches` / `failure_at` / `key_bits` / `key_status` / `result`。

**`failure_at` 定位**：header 失败给 `{"header": "<name>", "offset": <int>}`；
body 失败给 `{"body_line": <int>}`（1-based，指规范化后第一处不匹配的行）。

**`key_status`**：`ok` / `revoked`（`p=` 为空）/ `missing`（快照无记录）/ `weak`（<1024 位）。
`missing` → `undecidable`；`weak` → `fail`（RFC 8301 §3.2 是 MUST）。
`a=ed25519-sha256` → `undecidable` + 告警「本工具不支持该算法」（见 `plan/02` §4）。

### 3.4 `modules/dmarc.py`（M4）

**tree walk**：Author → Org → PSD 三跳，每跳记 `(qname, answered, record_or_reason)`。
命中即停。三跳全空 → `none`（不是 `fail`）。

**双算对齐**：`spf_align` / `dkim_align` 各出 `relaxed` 与 `strict` 两个布尔值，
**不合并成一个**——诊断时两者差异本身就是信息。

**旧标签告警**：`pct` / `rf` / `ri` 出现即 `warnings` 追加"已被 RFC 9989 删除"，
**不得静默忽略**（题面 M3 验收 2）。`psd` / `np` / `t` 正常解析并进输出。

**PSL 版本**：输出必带 `psl_version` + `psl_date`；来自快照，不读冻结件以外的东西。

### 3.5 `modules/reconcile.py`（M5）

**三分类**：`consistent` / `contradiction` / `undecidable`。

**硬约束**：

- `contradiction` 的 `explanations` ≥ 2，每条带 `hypothesis` + `verify`（具体要查什么）。
- `authserv_id` 不在 `trusted_authserv_ids` 里，或不可解析 → `undecidable`（fail-closed）。
- `--strict-evidence`：输出全文禁词（K10）；`strict_evidence_ok` 自检位为 false 时非零退出。

### 3.6 `modules/whatif.py`（M5）

**做法**：改 `Snapshot` 或 `query` 的**副本**，重跑 M2–M4，与基线账本做**结构差分**。
不重写求值器（题面 M5 明文要求）。

**差分可复算**：`diff` 子命令吃两份 `verdict.json`，输出逐字段差异；
且 `diff(baseline, candidate)` 的结果必须能反推出 `candidate`（测试断言）。

**RUA 关联**：吃 `rua.json`（parsedmarc 导出的最小结构），按 `source_ip` / 域 / 对齐结论聚类，
输出"上 `p=reject` 会打断谁"。缺 `rua.json` → `undecidable` + 所需输入清单，**不猜**。

## 4 错误与边界

| 情况 | 处理 | 退出码 |
|---|---|---|
| 文件不存在 / 不可读 | `InputError`，消息含相对路径 | 3 |
| JSON 语法错 | `InputError` + 行列号 | 3 |
| `schema_version` 不支持 | `InputError` + 支持版本列表 | 3 |
| `.eml` 无 `DKIM-Signature` | 不是错误：`dkim` 判定为 `none`，其余照常 | 按其余结果 |
| 快照缺必需的 key 记录 | `undecidable`（不是 `fail`） | 2 |
| 未捕获异常 | `InternalError`，**打印栈**，不吞 | 4 |
| 参数错（argparse） | `SystemExit(2)` → **CLI 入口统一转成 3**（输入错误） | 3 |

> 最后一条是刻意统一：argparse 默认 `exit 2` 与 `undecidable` 的 `2` 语义冲突。
> 入口捕获 `SystemExit(2)` 并转 3，测试锁定这一行为（`test_contract.test_argparse_exit_code`）。
