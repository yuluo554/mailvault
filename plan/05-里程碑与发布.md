**M4 口径更正（相对初版计划）**：

1. 初版写"tree walk 三跳，命中即停"。**实测按 RFC 9989 §4.10 实现后**：走查必须走到
   标签用尽或 `psd=n`/`psd=y`，因为 §4.10.2 的 Organizational Domain 选择要按
   "从长到短"看**全部**命中记录；"Author → Org → PSD 偏好顺序"是 §4.10.1 的策略发现
   层面，两者不是一回事。
2. 初版把 PSL 的 Organizational Domain 当输出。**RFC 9989 §4.10 已用 tree walk 取代
   PSL 方法**，所以 `organizational_domain` 只由走查得出，PSL 值另存为
   `psl_organizational_domain`（对照用）。B.4.3 的 `psd=y` 形态下两者必然不同。
3. 初版未提 `np=` 的**存在性歧义**。实装后新增：带 `np=` 而快照缺 Author 域存在性证据
   → `disposition_status = "undecidable"`、`disposition = null`（**不猜**）。
4. **空反向路径（`MAIL FROM:<>`）时 SPF 域是 HELO 域**，不是"没有身份"。§3.2.4 指向
   RFC 7208 §2.4："the 'MAIL FROM' identity [is] the mailbox composed of the local-part
   'postmaster' and the 'HELO' identity"。初版按"无身份"实装过一轮，会把本该 relaxed
   对齐判 pass 的报文判成 fail——**按 RFC 原文更正**，并加了两条测试（有 HELO / 无 HELO）。

**M5 口径更正 / 实装期决定（相对初版计划）**：

1. 初版把对账写成"三分类"就完了，没说**矛盾怎么进退出码**。实装后定：汇总成**一条**
   `reconcile.cross_check`，全一致 → `pass`、有矛盾或判不了 → `undecidable`、无 AR → `none`
   （K19）。**矛盾不进 `fail`**——题面风险 ③ 明说这会被读成"你被黑了"。
2. 初版没写 `trusted_authserv_ids` 为空时的语义。实装后定：**空 ≠ 全部可信**，
   一律 fail-closed（K20）。
3. 初版把 `diff` 的退出码留着没定。实装后定 **0**：它是比较命令，"有差异"是正常输出；
   映射成 1 会与"1 = 存在 fail"撞语义。
4. 初版 `--change` 只列了 `p=` / `all=` / `include:`。实装后键集定为
   `p|sp|np|t|all|include`（K25），且 `include:` 用**冒号**形态（与 M0 冻结的文档示例一致）。
5. `--strict-evidence` 从"只有 `audit`"扩到 `whatif` / `diff`（K24）：两份产物同样会被归档。
6. `--rua` 缺省**不算** undecidable（K23）：可选输入缺省若影响退出码，"不带 `--rua` 就
   永远非零"，那条功能就成了噪声。它在产物里仍如实标 `status: "undecidable"` + 所需输入清单。
7. `diff` 的 ops **只覆盖能唯一定义重建顺序的结构**：列表只在"等长且元素都是对象"时
   按下标递归，长度不同就整表当一个值（K22）。按下标对不等长列表做增删无法唯一定义
   重建顺序——那个洞比"差分粒度粗一点"严重得多。
8. 卫生门新增一条**结构性前缀剥离**（剥 RFC 8601 的 `ptype.property=`），并配阴性对照
   （`plan/04` §3.6）。这是"改数据去迁就门"的替代做法。
9. **`.eml` fixture 补上 `.gitattributes` 的 `-text`**（`plan/04` §4 的实测记录）：
   `* text=auto eol=lf` 会把报文里的 CRLF 归一，而 DKIM 的 `bh=` 是对规范化字节算的——
   裸 clone 之后四个生成器的 `--check` 会全部报不一致。这条故障在本机看不出来，
   所以另加 `tests/test_determinism.py::test_eml_fixtures_need_crlf_and_must_be_declared_minus_text`
   盯住（同时断言"fixture 里真有 CRLF"与"规则真在"）。附带完成了一次**本地 bare 仓库
   round-trip 直跑**（pytest 436 + 七条门 + 四个生成器 `--check` 全绿）——这是 V6 的
   前置条件，**不替代** M6 的"真下载 + 解包"复核。

## 4 发布口径（M6 用，本棒只登记）

### 4.1 发布物形态

**手工源码包**（`git archive` 口径），不是 GitHub 自动生成的 Source code 包——
后者的 sha256 本地复算不出来。附件 `mailvault-1.0.0.tar.gz` 由 CI 从 tag 树构建。

### 4.2 版本"三处一致"

| 处 | 判据 |
|---|---|
| `mailvault/__init__.py::__version__` | **唯一真源** |
| `pyproject.toml` | `dynamic = ["version"]` + `attr = "mailvault.__version__"`（不写第二份） |
| `README.md` 状态行 | 含 `v${version}` |

一条测试同时断言三处（M6 落地 `tests/test_version_consistency.py`）。

### 4.3 tag 后纪律

- `POST_TAG_SCOPE`：改动 ⊆ 非交付面（`plan/` `tests/` `tools/` `docs/` `README` `AGENTS`）
- `DELIVERABLE_UNCHANGED`：交付面前缀（`mailvault/` `pyproject.toml`）**零差异**
- tag 树内的留档**不写** tag 的 OID / 包 sha256（自指，写一次失效一次）；字面值放 tag 之后

### 4.4 CI 口径

未推送 = 未跑 CI。**M0–M5 的 DoD 里不写"CI 绿"**，只写：

> 本地等价校验（未接远端，CI 待首推验证）：布局门全绿 + 变异变红 + AST 守门 + `pytest` 全绿 + CLI 冒烟。

**M6 已接远端**，因此从 M6 起 CI 是真的：

| 项 | 实录 |
|---|---|
| 远端 | `git@github.com:yuluo554/mailvault.git`（公开） |
| push 数 = run 数 | **6 = 6**（截至 `858f944`；判据落在「每次 push 恰好一条 run」这一不变量上，不靠改数字维持） |
| `main` 首推 | run `39526291036` — 四矩阵绿 + offline job 红（`--network none` 容器冲突，已修） |
